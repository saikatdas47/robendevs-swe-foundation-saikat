# SDLC, Agile and Requirements

The examples follow a feature that lets a ShopNest merchant download an order report.

## Software development life cycle

The **SDLC** describes how a change moves from an idea to a running system and how it is maintained afterward. These activities can repeat as the team learns more.

| Activity | Order report example |
| --- | --- |
| Discover and plan | Find out who needs the report, which fields matter, and what problem it solves. |
| Design | Agree on permissions, tenant scope, CSV columns, and how large exports run. |
| Build | Implement the request, export job, and download flow. |
| Verify | Test permissions, file contents, limits, and job failures. |
| Release | Enable the feature for a small group of merchants and watch export failures. |
| Operate and improve | Investigate slow jobs, review usage, and fix problems from production. |

**Agile** means delivering usable changes in small steps, getting feedback, and adapting the plan. A team might deliver one fixed report first, then add custom columns after seeing how merchants use it. Scrum and Kanban give teams different ways to organise that work. [Agile Manifesto](https://agilemanifesto.org/)

## Scrum, sprints and events

A **Sprint** is a fixed period of one month or less. The Scrum Team works toward a Sprint Goal and creates a usable Increment. The Product Owner orders the Product Backlog, Developers plan and build the Increment, and the Scrum Master helps the team use Scrum effectively.

| Event | Purpose | Example |
| --- | --- | --- |
| Sprint Planning | Agree why the Sprint matters, what can be done, and how to start. | Set a goal to let staff request and download a basic report. |
| Daily Scrum | Developers inspect progress toward the Sprint Goal and adapt their plan. | Move someone from formatting the CSV to fixing a blocker in the worker. |
| Sprint Review | Inspect the outcome with stakeholders and discuss what to do next. | Try the export with merchants and learn that date filters matter more than extra columns. |
| Sprint Retrospective | Improve the team's way of working. | Add a shared test fixture after discovering that review stalled on missing sample data. |

Backlog refinement is ongoing work that can happen during a Sprint. A usable Increment can be released before the Sprint Review. [Scrum Guide](https://scrumguides.org/scrum-guide.html)

## Kanban and flow

A Kanban board makes work and waiting visible. Define where work starts and finishes, set work-in-progress limits, and pull the next item when capacity opens. Example columns are Ready, In Progress, Review, and Done. If Review is full, help finish reviews before starting another feature.

Track throughput as finished items per period, cycle time as time from start to finish, and work item age as time since an unfinished item started. Kanban fits a steady stream of requests, bugs, or operations work. A team can also use flow measures and WIP limits within Scrum.

## Requirements, stories and acceptance criteria

| Type | What it describes | Example |
| --- | --- | --- |
| Functional requirement | What the product must do. | Staff with report permission can request a CSV for a chosen date range. |
| Non-functional requirement | A quality or constraint for that behaviour. | Under agreed load, 95% of exports with up to 10,000 orders finish within 30 seconds. |

A user story connects a role, an action, and a benefit.

> A shop manager needs to export orders for a chosen date range to reconcile sales.

Acceptance criteria describe observable results for this story.

- Given a staff member with report permission and a valid date range, when an export is requested, then the platform creates a job and returns its ID.
- Given two shops with orders on the same date, when one shop exports that date, then the CSV contains only its orders.
- Given a reversed date range, when an export is requested, then the API returns a validation error and creates no job.
- Given a completed job, when authorised staff request its file, then the CSV contains the agreed headers and order rows.

## Jira work items, boards and workflows

| Work item | Use | Example |
| --- | --- | --- |
| Epic | A larger outcome with several related work items. | Merchant reporting |
| Story | A piece of value for a user. | Export orders for a date range |
| Task | A concrete piece of work. | Configure export storage expiry |
| Bug | A difference between expected and actual behaviour. | The end date is left out of an export |
| Spike | A time-boxed investigation with a decision or findings. | Compare export approaches for 10,000 rows |

A spike can be a custom work type, a task, or a labelled item depending on Jira configuration. A **workflow** defines statuses and allowed transitions. A **board** shows selected work items in columns that map to statuses. A single column can represent multiple statuses.

Example workflow. Backlog → Ready → In Progress → In Review → Done. Review can return a change to In Progress. A Scrum board can group work into sprints. A Kanban board can show a continuous flow and highlight work piling up in one column. [Jira work item guide](https://www.atlassian.com/software/jira/guides/issues/overview)
