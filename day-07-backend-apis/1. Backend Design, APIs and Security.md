# Day 07 — Backend Design, APIs and Security

I build a small workshop API with Node.js, Express 5 and JWT. Anyone can browse workshops. Only someone with a valid token and the editor role can create one.

## 1. REST fundamentals

A resource is something I expose through the API, such as a workshop. I identify a collection with `/api/v1/workshops` and an individual item with `/api/v1/workshops/42`. JSON is one representation of that resource. I use the HTTP method to say what I want to do.

| Method | My workshop example | Typical successful response |
| --- | --- | --- |
| `GET` | Read the collection or one workshop | `200 OK` with JSON |
| `POST` | Create a workshop in the collection | `201 Created` with JSON and a `Location` header |
| `PUT` | Replace the representation at a known workshop URL | `200 OK` with JSON or `204 No Content` |
| `PATCH` | Change selected fields, such as the seat count | `200 OK` or `204 No Content` |
| `DELETE` | Remove a workshop | `204 No Content` with no response body |

I keep GET read-only. Retrying the same PUT or DELETE should leave the resource in the same intended state, even if the response status changes. Repeating a POST can create another record, so I decide separately whether the endpoint needs an idempotency key. [HTTP semantics](https://www.rfc-editor.org/rfc/rfc9110.html)

For creation, I send `Content-Type: application/json` and a body such as:

```json
{
  "title": "Backend APIs",
  "topic": "backend",
  "seats": 10
}
```

A successful response includes `Location: /api/v1/workshops/3` and the created resource.

```json
{
  "id": 3,
  "title": "Backend APIs",
  "topic": "backend",
  "seats": 10
}
```

## 2. How I design the endpoints

I use plural nouns and keep the same naming pattern across collections. I put the major API version in the path for this project. If I change an existing field in a way that breaks callers, I can publish a v2 contract and give callers time to migrate. I document changes within v1 as well, including new optional fields.

```text
GET /api/v1/workshops?topic=backend&sort=-seats&page=1&limit=10
```

I apply the filter first, sort the matches by seats descending, then take the requested page. I use ID as a tie-breaker when seats are equal. The response contains `items`, `page`, `limit`, `total` and `hasNextPage`. If the collection is empty or the requested page is past the end, I return `200` with an empty `items` array. A request for a specific workshop ID that does not exist gets `404`.

I use page and limit here because they are easy to inspect. When a large feed changes frequently, offset-based pages can shift between requests. I can move to a cursor based on a stable sort order with a unique tie-breaker. I cap the page size either way.

## 3. What I validate and how I report errors

I validate path parameters, query parameters and JSON bodies at the API boundary. For creation I require a title, a lowercase topic slug and a seat count from 1 to 1000. I reject unknown body fields so a typo is visible and callers cannot write fields such as `id`. I check authorisation and business rules on the server, even if the frontend already checks the same input.

| Status | When I send it here |
| --- | --- |
| `400 Bad Request` | The JSON is malformed or the ID or query parameters have an invalid format |
| `401 Unauthorized` | A required bearer token is missing, invalid or expired |
| `403 Forbidden` | The token is valid but the user lacks the editor role |
| `404 Not Found` | The route or requested workshop is missing |
| `413 Content Too Large` | The body exceeds the JSON size limit |
| `415 Unsupported Media Type` | The request uses an unsupported content type or encoding |
| `422 Unprocessable Content` | The JSON was read successfully but its fields fail validation |
| `500 Internal Server Error` | An unexpected failure occurred and the client gets a generic message |

I keep the same JSON error shape throughout the API. The client can branch on `code` and display field messages beside the relevant inputs. For example, a body with zero seats gets:

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Check the workshop fields",
    "fields": {
      "seats": "Use a whole number from 1 to 1000"
    }
  }
}
```

## 4. Routes, controllers, services and repositories

```text
HTTP request → route and middleware → controller → service → repository
HTTP response ← controller ← result from service ← record from repository
                   │
                   └── errors go to the shared error middleware
```

- **Route** — I match the method and path and attach middleware such as JWT verification.
- **Controller** — I read and validate HTTP input, call the service and choose the response status and body.
- **Service** — I enforce application rules. Here I check whether the authenticated user is allowed to create a workshop.
- **Repository** — I handle storage and retrieval. For this exercise I use memory. In a database version I would filter, sort and paginate in the query.

### I wire the layers together in Express

I use one script for the lesson so I can run the complete example. I save this as `server.mjs` in a practice folder, run `npm init -y` and install the packages with `npm install express@5 jsonwebtoken`.

```javascript
import express from "express"
import jwt from "jsonwebtoken"

const secret = process.env.JWT_SECRET
if (!secret) throw new Error("Set JWT_SECRET before starting")

const issuer = "workshop-auth"
const audience = "workshop-api"

class ApiError extends Error {
  constructor(status, code, message, fields) {
    super(message)
    this.status = status
    this.code = code
    this.fields = fields
  }
}

function requireAuth(req, res, next) {
  const match = /^Bearer\s+(\S+)$/i.exec(req.get("Authorization") ?? "")
  let claims

  try {
    if (match) {
      claims = jwt.verify(match[1], secret, {
        algorithms: ["HS256"],
        issuer,
        audience
      })
    }
  } catch {
    claims = undefined
  }

  if (typeof claims?.sub !== "string" || typeof claims.exp !== "number") {
    res.set("WWW-Authenticate", match ? 'Bearer error="invalid_token"' : "Bearer")
    return next(new ApiError(401, "UNAUTHENTICATED", "A valid bearer token is required"))
  }

  req.user = claims
  next()
}

function positiveInteger(value, max) {
  if (typeof value !== "string" || !/^[1-9]\d*$/.test(value)) return null

  const number = Number(value)
  return Number.isSafeInteger(number) && number <= max ? number : null
}

function readListOptions(query) {
  const { topic, sort = "id", page = "1", limit = "10" } = query
  const pageNumber = positiveInteger(page, 1_000_000)
  const pageSize = positiveInteger(limit, 50)
  const validTopic = topic === undefined ||
    (typeof topic === "string" && /^[a-z0-9-]{1,30}$/.test(topic))

  if (!pageNumber || !pageSize || !validTopic ||
      !["id", "seats", "-seats"].includes(sort)) {
    throw new ApiError(400, "INVALID_QUERY", "Check topic, sort, page and limit")
  }

  return { topic, sort, page: pageNumber, limit: pageSize }
}

function readWorkshop(body) {
  if (!body || typeof body !== "object" || Array.isArray(body)) {
    throw new ApiError(422, "VALIDATION_FAILED", "Send a workshop object")
  }

  const { title, topic, seats } = body
  const fields = {}

  if (typeof title !== "string" || !title.trim() || title.trim().length > 100) {
    fields.title = "Use a title from 1 to 100 characters"
  }
  if (typeof topic !== "string" || !/^[a-z0-9-]{1,30}$/.test(topic)) {
    fields.topic = "Use 1 to 30 lowercase letters, digits or hyphens"
  }
  if (!Number.isInteger(seats) || seats < 1 || seats > 1000) {
    fields.seats = "Use a whole number from 1 to 1000"
  }
  if (Object.keys(body).some((key) => !["title", "topic", "seats"].includes(key))) {
    fields.body = "Only title, topic and seats are accepted"
  }
  if (Object.keys(fields).length) {
    throw new ApiError(422, "VALIDATION_FAILED", "Check the workshop fields", fields)
  }

  return { title: title.trim(), topic, seats }
}

const records = [
  { id: 1, title: "HTTP Basics", topic: "backend", seats: 8 },
  { id: 2, title: "CSS Grid", topic: "frontend", seats: 12 }
]
let nextId = 3

const workshopRepository = {
  list({ topic, sort, page, limit }) {
    const matches = records.filter((item) => topic === undefined || item.topic === topic)
    matches.sort((left, right) => {
      if (sort === "seats") return left.seats - right.seats || left.id - right.id
      if (sort === "-seats") return right.seats - left.seats || left.id - right.id
      return left.id - right.id
    })

    const start = (page - 1) * limit
    return {
      items: matches.slice(start, start + limit),
      page,
      limit,
      total: matches.length,
      hasNextPage: start + limit < matches.length
    }
  },

  find(id) {
    return records.find((item) => item.id === id)
  },

  create(input) {
    const workshop = { id: nextId++, ...input }
    records.push(workshop)
    return workshop
  }
}

const workshopService = {
  list(options) {
    return workshopRepository.list(options)
  },

  find(id) {
    const workshop = workshopRepository.find(id)
    if (!workshop) throw new ApiError(404, "NOT_FOUND", "Workshop not found")
    return workshop
  },

  create(user, input) {
    if (user.role !== "editor") {
      throw new ApiError(403, "FORBIDDEN", "An editor role is required")
    }
    return workshopRepository.create(input)
  }
}

const workshopController = {
  list(req, res) {
    res.json(workshopService.list(readListOptions(req.query)))
  },

  find(req, res) {
    const id = positiveInteger(req.params.id, Number.MAX_SAFE_INTEGER)
    if (!id) throw new ApiError(400, "INVALID_ID", "Use a positive integer ID")
    res.json(workshopService.find(id))
  },

  create(req, res) {
    const workshop = workshopService.create(req.user, readWorkshop(req.body))
    res.location(`/api/v1/workshops/${workshop.id}`).status(201).json(workshop)
  }
}

function requireJson(req, res, next) {
  if (!req.is("application/json")) {
    return next(new ApiError(415, "UNSUPPORTED_MEDIA_TYPE", "Send application/json"))
  }
  next()
}

const router = express.Router()
router.get("/", workshopController.list)
router.get("/:id", workshopController.find)
router.post("/", requireAuth, requireJson, express.json({
  limit: "16kb",
  strict: false
}), workshopController.create)

const app = express()
app.use("/api/v1/workshops", router)
app.use((req, res, next) => {
  next(new ApiError(404, "NOT_FOUND", "Route not found"))
})

app.use((error, req, res, next) => {
  if (res.headersSent) return next(error)

  let problem = error

  if (error.type === "entity.parse.failed") {
    problem = new ApiError(400, "INVALID_JSON", "Send valid JSON")
  } else if (error.type === "entity.too.large") {
    problem = new ApiError(413, "BODY_TOO_LARGE", "JSON body exceeds 16 KB")
  } else if (["encoding.unsupported", "charset.unsupported"].includes(error.type)) {
    problem = new ApiError(415, "UNSUPPORTED_MEDIA_TYPE", "Unsupported body encoding")
  } else if (error instanceof URIError) {
    problem = new ApiError(400, "INVALID_PATH", "The URL could not be decoded")
  } else if (!(error instanceof ApiError)) {
    console.error({ event: "request_failed", errorType: error.name })
    problem = new ApiError(500, "INTERNAL_ERROR", "Something went wrong")
  }

  res.status(problem.status).json({
    error: { code: problem.code, message: problem.message, fields: problem.fields }
  })
})

app.listen(3000, "127.0.0.1")
```

### I try the API locally

In the practice folder I generate a secret and a short-lived demo token, then start the server. The command that signs the token simulates a trusted issuer for this exercise. In an application, the issuer verifies the account before assigning the editor role.

```sh
export JWT_SECRET="$(node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))')"
node -e 'console.log(require("jsonwebtoken").sign({ role: "editor" }, process.env.JWT_SECRET, { algorithm: "HS256", subject: "user-1", issuer: "workshop-auth", audience: "workshop-api", expiresIn: "15m" }))' > .demo-token
node server.mjs
```

From a second terminal in the same folder, I check filtering, then create a workshop.

```sh
curl -i 'http://127.0.0.1:3000/api/v1/workshops?topic=backend&sort=-seats&page=1&limit=10'

curl -i http://127.0.0.1:3000/api/v1/workshops \
  -H "Authorization: Bearer $(cat .demo-token)" \
  -H 'Content-Type: application/json' \
  --data '{"title":"Backend APIs","topic":"backend","seats":10}'
```

The first call returns `200`. The second should return `201` and the new resource URL. If I omit the bearer header, I expect `401`. If I change the seat count to zero and submit with a valid editor token, I expect `422`. I keep the demo token file local and delete it after the exercise.

I verify the JWT's signature, algorithm, issuer, audience and expiry before I trust the claims. Verification answers who is making the request. The service checks whether that identity can create a workshop. A signed JWT can still be read by whoever has it, so I keep secrets out of the payload and use HTTPS when sending it outside this localhost exercise.
