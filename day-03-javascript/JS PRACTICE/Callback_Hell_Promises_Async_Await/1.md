# How JavaScript timers work

**The timer starts when JavaScript reaches `setTimeout`. The code inside runs later, when its waiting time has passed and JavaScript is free.**

## The code

```js
const fs = require("node:fs");

// Block A — synchronous
console.log("1");

// Block B — starts a timer; inside code runs later
setTimeout(() => {
    console.log("2");
}, 2000);

// Block C — starts a timer; inside code runs later
setTimeout(() => {
    console.log("4");

    fs.writeFile("output.txt", "Hello from the timer!", (error) => {
        if (error) {
            console.error("Failed to write file:", error);
            return;
        }

        console.log("File written successfully!");
    });
}, 0);

// Block D — synchronous
for (let i = 0; i < 1000000; i++) {
    console.log("loop iteration: " + i);
}

// Block E — starts a timer; inside code runs later
setTimeout(() => {
    console.log("6");
}, 1000);

// Block F — synchronous
console.log("3");
```

## Synchronous and asynchronous

**Synchronous:** JavaScript finishes the current work before moving to the next statement.

**Asynchronous:** JavaScript schedules or starts something, then continues other work. The code waiting for the result runs later.

Starting a timer happens immediately. Running the code inside that timer happens later.

## Step 1: Block A runs

```js
console.log("1");
```

It immediately prints:

```text
1
```

## Step 2: Block B starts the 2-second timer

```js
setTimeout(() => {
    console.log("2");
}, 2000);
```

The timer starts counting now.

JavaScript does not wait here. It moves to Block C.

**Nothing prints from Block B yet.**

## Step 3: Block C starts the 0-second timer

```js
setTimeout(() => {
    console.log("4");
    // Write the file
}, 0);
```

The timer is scheduled, but its inside code must wait until the current JavaScript work finishes.

So:

- `"4"` does not print yet.
- File writing does not start yet.

**Zero delay does not mean “run immediately.”**

## Step 4: Block D runs the loop

```js
for (let i = 0; i < 1000000; i++) {
    console.log("loop iteration: " + i);
}
```

The loop is synchronous. JavaScript completes all its iterations before moving to Block E.

It prints:

```text
loop iteration: 0
loop iteration: 1
...
loop iteration: 999999
```

While the loop runs, the timers keep counting down.

Even if a timer finishes waiting, its inside code cannot interrupt the loop.

**The waiting time can finish while JavaScript is busy.**

## Step 5: Block E starts the 1-second timer

```js
setTimeout(() => {
    console.log("6");
}, 1000);
```

JavaScript has now finished the loop and reached this line.

The 1-second timer starts **now**, after the loop.

It was not counting during the loop.

**Nothing prints from Block E yet.**

## Step 6: Block F runs

```js
console.log("3");
```

It immediately prints:

```text
3
```

The current synchronous work is now finished.

JavaScript can now run the waiting timer code.

## Step 7: Block C's inside code runs

In your output, it prints:

```text
4
```

Then this starts writing the file:

```js
fs.writeFile("output.txt", "Hello from the timer!", ...);
```

File writing is asynchronous. JavaScript starts the operation and can continue other work while the system writes the file.

The success message waits until writing finishes and JavaScript has a chance to show it.

## Step 8: Block B's inside code runs

In your run, the 2-second waiting time has already passed during the earlier work.

It prints:

```text
2
```

The timer did not restart after the loop. It had been counting since Block B.

## Step 9: The file success message runs

In your run, the next message is:

```text
File written successfully!
```

This means the file write finished successfully and JavaScript got a chance to print the result.

Its position can change depending on how long writing takes.

## Step 10: Block E's inside code runs

It prints:

```text
6
```

Its timer started after the loop, so it runs later in your output.

## Your output explained

```text
1                          → Block A

loop iteration: 0          → Block D
...
loop iteration: 999999      → Block D finishes

3                          → Block F

4                          → Block C's inside code runs
                             File writing starts here

2                          → Block B's inside code runs

File written successfully! → File write finished

6                          → Block E's inside code runs
```

This explains your recorded output. Timing can change between runs.

## Why this is different from parallel work

Parallel work means two jobs are actually being done at the same time.

Here, the timer counts down while the loop runs. But the loop and the JavaScript inside the timer do not run at the same time.

The timer's code waits for its turn.

The system can handle file writing while JavaScript continues other work. But the JavaScript that prints the file result also waits for its turn.

### A simple example

Imagine one cook:

1. The cook sets a timer for 2 minutes.
2. The cook chops vegetables for 3 minutes.
3. The timer rings after 2 minutes.
4. The cook finishes chopping before checking the oven.

The timer counted down while the cook worked. But setting the timer did not create a second cook.

## Remember

**Timer starts now → time passes → current JavaScript work finishes → waiting timer code gets a turn.**

The delay is a minimum waiting time. It does not guarantee the exact time when the code will run.
