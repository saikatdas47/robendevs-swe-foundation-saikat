# SQL Queries

I run these examples after loading the [shop schema and sample data](1.%20Relational%20Modelling.md). Prices and totals are in cents. In the results below, each parenthesised group is one row and its values follow the order of the selected columns.

## SELECT

I use `SELECT` to pick columns and calculate values. `FROM` names the table and `WHERE` filters its rows. `ORDER BY` sorts the result, and `LIMIT` keeps only the first few rows after sorting. I add a second sort column so ties have a clear order.

```sql
SELECT name, price_cents
FROM products
WHERE price_cents >= 500
ORDER BY price_cents DESC, product_id
LIMIT 2;
```

Result — `(Bag, 2500)`, `(Mug, 900)`.

I use `DISTINCT` when I want each selected value or combination of values once. To find missing values, I use `IS NULL`. A comparison such as `= NULL` does not test for missing values.

```sql
SELECT DISTINCT status
FROM orders
ORDER BY status;
```

Result — `(paid)`, `(pending)`.

## JOIN

I use `JOIN` when the columns I need live in different tables. `ON` describes how the rows match. The short names `oi` and `p` let me say which table each column comes from. An `INNER JOIN` returns only matching rows.

```sql
SELECT oi.order_id, p.name, oi.quantity,
       oi.quantity * oi.unit_price_cents AS line_total_cents
FROM order_items AS oi
INNER JOIN products AS p ON p.product_id = oi.product_id
WHERE oi.order_id = 101
ORDER BY p.product_id;
```

Result — `(101, Notebook, 2, 1000)`, `(101, Pen, 3, 600)`. I use the sale price stored on the order item.

A `LEFT JOIN` keeps every row from the left table. When there is no match, the columns from the right table are `NULL`. I put the paid-order filter in `ON` so that customers without paid orders stay in the result. If I move that filter to `WHERE`, those customers disappear.

```sql
SELECT c.name, o.order_id
FROM customers AS c
LEFT JOIN orders AS o
    ON o.customer_id = c.customer_id AND o.status = 'paid'
ORDER BY c.customer_id, o.order_id;
```

Result — `(Asha, 101)`, `(Asha, 102)`, `(Rafi, 104)`, `(Mina, NULL)`. Asha appears twice because she has two paid orders.

## GROUP BY

I use `GROUP BY` to turn several rows into one result per group. `COUNT` counts rows or non-null values, `SUM` adds values, and `AVG` finds the mean. I use `WHERE` to filter rows before grouping and `HAVING` to filter the groups after SQL calculates the totals.

```sql
SELECT o.customer_id, SUM(oi.quantity * oi.unit_price_cents) AS paid_total_cents
FROM orders AS o
JOIN order_items AS oi ON oi.order_id = o.order_id
WHERE o.status = 'paid'
GROUP BY o.customer_id
HAVING SUM(oi.quantity * oi.unit_price_cents) >= 1000
ORDER BY paid_total_cents DESC, o.customer_id;
```

Result — `(1, 4100)`. Rafi's paid total is 400 cents, so his group fails the `HAVING` condition.

To count orders after a `LEFT JOIN`, I count `o.order_id`. It skips the `NULL` in Mina's row. `COUNT(*)` would count her unmatched row as one. If I join order items too, I may need `COUNT(DISTINCT o.order_id)` because an order can have several items.

```sql
SELECT c.name, COUNT(o.order_id) AS order_count
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.customer_id
GROUP BY c.customer_id, c.name
ORDER BY c.customer_id;
```

Result — `(Asha, 2)`, `(Rafi, 2)`, `(Mina, 0)`.

## Subqueries

A subquery is a query inside another query. I choose the form based on what the outer query needs.

### Compare with one value

The inner query returns one value, the average product price of 1,025 cents. The outer query compares each product with that value.

```sql
SELECT name, price_cents
FROM products
WHERE price_cents > (SELECT AVG(price_cents) FROM products)
ORDER BY price_cents DESC, product_id;
```

Result — `(Bag, 2500)`.

### Match any value in a list

With `IN`, I check whether a value appears in the rows returned by a one-column subquery. A customer with several paid orders still appears once because the outer query reads from `customers`.

```sql
SELECT name
FROM customers
WHERE customer_id IN (
    SELECT customer_id
    FROM orders
    WHERE status = 'paid'
)
ORDER BY customer_id;
```

Result — `(Asha)`, `(Rafi)`.

### Check whether a matching row exists

This is a **correlated subquery** because it refers to `c.customer_id` from the outer query. I read `NOT EXISTS` as “keep this customer if there is no order for them.” `SELECT 1` is enough because the check only needs to know whether a row exists.

```sql
SELECT c.name
FROM customers AS c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders AS o
    WHERE o.customer_id = c.customer_id
)
ORDER BY c.customer_id;
```

Result — `(Mina)`.

### Use a subquery as a table

Here I first count orders per customer. The outer query treats those counts as rows in a temporary result and averages the counts. Customers with zero orders are included because the inner query uses a left join.

```sql
SELECT ROUND(AVG(order_count), 2) AS average_orders
FROM (
    SELECT COUNT(o.order_id) AS order_count
    FROM customers AS c
    LEFT JOIN orders AS o ON o.customer_id = c.customer_id
    GROUP BY c.customer_id
) AS customer_counts;
```

Result — `(1.33)`, from averaging 2, 2, and 0.
