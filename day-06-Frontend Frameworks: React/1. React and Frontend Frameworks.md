# Day 06 — React and Frontend Frameworks

I use React as my main reference and continue with the workshop signup page from Day 05. I use the same page to compare how Angular, AngularJS, Vue and Svelte express similar ideas.

## 1. Components, props and JSX

I split the page into a parent that holds the filter and a child that shows one workshop. A React function component receives props and returns the UI for those inputs. I treat props as read-only. If a child needs the parent to change something, I can pass it a callback prop.

```jsx
function WorkshopCard({ title, availableSeats }) {
  return (
    <article>
      <h3>{title}</h3>
      <p>{availableSeats} seats left</p>
    </article>
  )
}
```

When I write `<WorkshopCard title="HTML and CSS" availableSeats={3} />`, both values become props. I capitalize the component name and use braces to put a JavaScript expression inside JSX. The build converts JSX into JavaScript that creates React elements. React uses those elements to work out what to display.

In a template-based framework, I express the same layout in template markup. For example, I can write `<h3>{{ title }}</h3>` in an Angular or Vue template. Angular can loop with `@for`, Vue with `v-for`, and Svelte with `{#each}`. In JSX, I use JavaScript expressions such as `map()` to produce the elements. [React JSX](https://react.dev/learn/writing-markup-with-jsx)

## 2. Local state, events and rendering

I keep the search text in local state because the list and input belong to the same page. When the user types, the handler updates the state and React renders with the new query. I calculate the filtered list from the current query on each render.

```jsx
import { useState } from "react"

const workshops = [
  { id: "html-css", title: "HTML and CSS", availableSeats: 3 },
  { id: "rendering", title: "Browser Rendering", availableSeats: 0 }
]

function WorkshopCard({ title, availableSeats }) {
  return (
    <li>
      <h3>{title}</h3>
      <p>{availableSeats > 0 ? `${availableSeats} seats left` : "Sold out"}</p>
    </li>
  )
}

export default function WorkshopSearch() {
  const [query, setQuery] = useState("")
  const search = query.trim().toLowerCase()
  const matches = workshops.filter(({ title }) =>
    title.toLowerCase().includes(search)
  )

  return (
    <section>
      <h2>Find a workshop</h2>
      <label>
        Search workshops
        <input value={query} onChange={(event) => setQuery(event.target.value)} />
      </label>
      <button type="button" onClick={() => setQuery("")}>Clear</button>

      {matches.length === 0 ? (
        <p role="status">No workshops found</p>
      ) : (
        <ul>
          {matches.map(({ id, title, availableSeats }) => (
            <WorkshopCard key={id} title={title} availableSeats={availableSeats} />
          ))}
        </ul>
      )}
    </section>
  )
}
```

If I type `css`, only HTML and CSS remains. If I type `python`, I get the empty state. When I click Clear, both workshops return. I give each child a stable ID as its `key` so React can match the correct items if the list changes order. I pass a function to `onClick` so the reset happens when I click.

A state setter schedules an update. The current handler still sees the state snapshot from the render that created it. If the next value depends on the previous one, I can write `setCount((count) => count + 1)`. [React state snapshots](https://react.dev/learn/state-as-a-snapshot) · [React list rendering](https://react.dev/learn/rendering-lists)

## 3. Mounting, updating, unmounting and effects

I call it a mount when React adds the component to the committed tree, an update when the existing component commits changes and an unmount when React removes it. Rendering calculates the next UI. The commit applies the necessary DOM changes.

I use an Effect to synchronise with something outside React. For example, a workshop panel can set the browser tab title while it is visible. Here I assume this panel is the only component managing the title while mounted.

```jsx
import { useEffect } from "react"

export function WorkshopDetails({ title }) {
  useEffect(() => {
    const previousTitle = document.title
    document.title = `${title} | Workshops`

    return () => {
      document.title = previousTitle
    }
  }, [title])

  return <h2>{title}</h2>
}
```

```text
Open HTML and CSS → setup sets the title
Switch to Browser Rendering → old cleanup restores it → new setup sets the new title
Leave the details view → cleanup restores the original title
```

On an update with the same title, this Effect does not rerun. With a different title, React runs the old cleanup before setting up the new Effect. In development, Strict Mode can run an extra setup and cleanup cycle to surface missing cleanup. Effects run on the client. A subscription or timer uses the same pattern, with cleanup unsubscribing or clearing the timer.

I calculate the filtered list during render because it comes from existing data. If clicking Book sends a request, I start it from that click handler because the user action is what triggers it. [React useEffect](https://react.dev/reference/react/useEffect)

## 4. One-way and two-way binding

In React, I follow the value down from the state owner and the event back up from the input.

```text
State query ── value ──► Input
State setter ◄── onChange event ── Input
```

The search field above is **controlled** because React state supplies its current `value`. The change handler writes what the user typed back to state. This is why Clear can reset the visible text by changing the state.

I use an **uncontrolled** field when the browser can hold the current value and I only need to read it on submit. I give it `defaultValue` for the initial value and read it through the form.

```jsx
export function SignupForm({ onSignup }) {
  function handleSubmit(event) {
    event.preventDefault()
    const values = new FormData(event.currentTarget)
    onSignup(values.get("email"))
  }

  return (
    <form onSubmit={handleSubmit}>
      <label>
        Email address
        <input name="email" type="email" defaultValue="" required />
      </label>
      <button type="submit">Sign up</button>
    </form>
  )
}
```

I choose one mode for the lifetime of a field. For a controlled text field, I keep its value a string from the first render. For an uncontrolled field, changing `defaultValue` is not how I edit what the user has already typed.

With **two-way binding**, the template syntax expresses both directions. For a text field, the state updates the input and user input writes back to the state. Angular offers `[(ngModel)]="email"` for a native form control with `FormsModule`, AngularJS uses `ng-model`, Vue uses `v-model="email"`, and Svelte uses `bind:value={email}` with a writable value. React lets me write both steps explicitly with `value` and `onChange`. [React inputs](https://react.dev/reference/react-dom/components/input) · [Angular two-way binding](https://angular.dev/guide/templates/two-way-binding) · [Vue form bindings](https://vuejs.org/guide/essentials/forms.html) · [Svelte bind](https://svelte.dev/docs/svelte/bind)

## 5. Framework landscape

| Tool | What I work with | How I recognise its approach |
| --- | --- | --- |
| React | A UI library built around components, JSX and Hooks | I can choose my routing and other app tools, or use a framework built around React. Props flow down and handlers raise changes. |
| Angular | An application framework with TypeScript-oriented tooling, templates and dependency injection | It provides its own routing and forms packages. I can use template bindings and signals for reactive state. |
| AngularJS | The legacy JavaScript framework from the AngularJS 1.x line | I recognise directives such as `ng-repeat`, scope-based views and digest-based change detection. I study it when reading or migrating older code. |
| Vue | A progressive UI framework with reactive state and HTML-based templates | I often write a single-file component with template, script and styles. I can add official tools such as Vue Router as the app grows. |
| Svelte | A component framework that compiles components during the build | I write markup and logic in `.svelte` files. The compiler turns component code into code that updates the UI. SvelteKit provides app features such as routing. |

When I move the workshop example between tools, I look for the same design decisions. I find who owns the filter, how a child receives its inputs, what event updates the filter and how external resources are cleaned up. The syntax changes, but those decisions still matter.

AngularJS officially ended support in January 2022. I distinguish it from modern Angular when reading documentation or working in an older project.
